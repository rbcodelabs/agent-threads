Browser session card

When the agent drives the in-app browser, the chat shows one live card per session instead of a stack of generic tool pills. It updates in place, shows the real latest screenshot, and collapses to a compact chip once the session is over. When a page needs you to sign in, the same card switches to a distinct amber "you're in control" mode. Other directions live in variations/.

In the thread

Step the session through its lifecycle. Finished and ended sessions start collapsed; click the chip to expand. Click the viewport to open the screenshot larger, or use the steps button to see every action taken.

Agent driving

Sign-in handoff (you drive)

  • One card per session. The first browser_navigate creates it; every later browser_* call updates the caption, URL and step list in place until browser_close.
  • Real screenshot. The viewport shows the newest image from toolResultImages. Until one exists it shows the page-skeleton placeholder.
  • Steps keep the detail. The step list carries the same information the individual pills show today (verb, target, outcome), so grouping loses nothing.
  • Collapse when done. Finished and ended sessions become a one-line chip with a thumbnail, keeping long threads scannable. Errors stay expanded.
  • Accent. Teal is reserved for the agent browsing; violet stays with generic tools; red for failure; amber only ever means you are driving.
  • Take control is its own mode. When a page wants a sign-in, the card asks you in the chat (30s), then flips to a solid amber "You're in control" state, with a persistent chip by the composer, a privacy line, and one big Return control button. Try the amber row above.
