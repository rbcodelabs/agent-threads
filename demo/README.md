# Getting started with Geode Threads: demo video

A narrated, cue-synced walkthrough of Agent Threads running inside Geode.
`demo/engine/` is the product demo engine from the Agentic PM Playbook
(`skills/product-demo-video`), vendored here. Do not edit it in place; refresh it with the
playbook's `scripts/vendor-engine.ts demo`, which leaves the config alone.

```sh
npm install --prefix demo/engine           # once
export ELEVENLABS_VOICE_ID=<voice id>      # ELEVENLABS_API_KEY comes from the environment
npm run demo:doctor
npm run demo:all                           # build plugin + fixture -> voiceover -> record -> compose -> sync report
```

Output: `demo/out/getting-started-with-geode-threads.mp4`, with cue strips in `demo/out/sync/`.
Only scenes whose narration changed re-spend ElevenLabs credit (audio is cached in `demo/cache/`).

## How it works

Claude is never called. The plugin has a scripted harness, `src/ReplaySession.ts`, that
`HarnessFactory` returns for Claude threads **only** when the host process has
`CLAUDE_THREADS_DEMO_SCRIPT` set to a JSON file. Unset, nothing changes. The recording config
sets it, so every take replays the same streamed text, tool calls, permission card, sub-agents and
task list with no token cost.

| File | Role |
|---|---|
| `demo.config.json` | Narration (the locked storyboard script, word for word), cued on-screen actions, environment. Generated by `build-config.mts`; edit there and re-run it, or edit the JSON directly. |
| `replay-script.json` | Canned replies. Turns are matched by a regular expression on the prompt the demo types. |
| `fixture-vault/` | The notes the replies link to. `build-fixture.mts` adds the built plugin, a seeded `data.json` (projects, finished threads, settings), the layout and the replay script (all gitignored). |
| `build-fixture.mts` | `npm run demo:fixture` (builds the plugin first). |

## Recording host

Geode is the app under recording; the plugin rides in the fixture vault.

- Recording runs on a Linux host over ssh (`environment.record.host`, the `dev-builder` alias). The
  engine syncs this repo there, then the config's `setup` points the synced project's
  `node_modules/electron` at the Electron in a built Geode checkout on that host
  (`~/geode-gate`, also named by `target.app`). The step fails early if that checkout is missing.
- Compose and voiceover run on this machine. A Mac gives the real system font and dock icons.
- If ssh says `Permission denied (publickey)`, unlock the 1Password SSH agent.
- The engine only records on Linux (Xvfb + x11grab). To record on a Mac you need a Linux VM, or a new
  recorder; this demo does not do that.

## Scenes

The sandbox VM, browser agent and push-to-talk are left out on purpose (not reproducible on the
Linux recorder, or off by default). The closing scene shows Geode's own plugin catalog
(Settings, Community plugins) with Agent Threads listed.

Useful selectors, all verified against the running app: composer `.ct-input` (inside
`.workspace-leaf-content[data-type="claude-threads:chat"]`), dispatch box `.ct-agents-dispatch-input`,
`.ct-agents-row` (+ `-running`, `-permission`), `.ct-permission-card` buttons `.ct-permission-deny|allow|always`,
`.ct-tool-pill`, `.ct-tool-group-header`, `.ct-kanban-card`, `.ct-agent-pill`, `.ct-agent-row-button`,
`.ct-tasklist-pill`, `.ct-schedule-pill`.

## Gotchas

- Each click costs about a second (pointer move 700 ms plus settle). A cue that follows several
  clicks fires late; the recorder warns `late by Nms`. Move setup clicks into the end of the previous scene.
- The dispatch box loses focus after Enter, so each dispatch needs its own click.
- Geode re-adds its core sidebar tabs when they are missing, so the fixture lists them and marks Agents active.

## Launch hero clip (no narration)

`demo/hero.config.json` is a short, silent clip for the README (`voice.provider: "none"`). It reuses the same fixture and replay script.

```sh
npm run demo:fixture
node demo/engine/run.mts all --config demo/hero.config.json
```

The recording host needs a built Geode checkout at `~/geode-gate` (see Recording host above).

What the four scenes do, in order:

1. **ask**: click the Agents sidebar tab (Geode labels it "N threads", so the selector matches `aria-label*="thread"`), click **New thread**, and type the prompt. There is no project menu to pick from: on current Geode, New thread opens a composer you can type into straight away. An older config that clicked a project menu item will hang waiting for it.
2. **work**: hover a tool pill (optional) while the replay streams.
3. **subagents**: wait for the sub-agent pill, open its popover, and click the first sub-agent row (the row click is optional, so a missing row no longer fails the take).
4. **board**: open the Agent Board from the ribbon and hover the running card.

`target.readySelector` waits for the chat leaf (`.workspace-leaf-content[data-type="claude-threads:chat"]`) before the first scene starts.

A raw take is about 33 s with a long idle stretch while the replay finishes. Trim the idle part and speed the rest up about 1.1x, then convert to `docs/images/agent-threads-hero.gif` (880 px wide, 10 fps, `palettegen`/`paletteuse`, looping) and keep the trimmed `docs/images/agent-threads-hero.mp4` for X. The text in the clip is scripted replay content from `replay-script.json`, not live Claude output.
